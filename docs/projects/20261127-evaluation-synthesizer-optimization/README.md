# 评测题库逆向合成引擎健壮性重构与容量策略优化 (Evaluation Synthesizer Optimization)

- **时间：** 2026-11-27
- **目标：** 解决出题引擎题目数量膨胀与前端滑块限制割裂、大模型串行慢如蜗牛、无断点续传导致服务重启白跑的两大核心痛点，建立可控、并发、带 Checkpoint 的高可用出题体系。
- **影响模块：**
  - `evaluation/dataset_generator.py`（出题引擎核心：并发控制、断点续传、容量算法）
  - `lightrag_webui/src/features/evaluation/EvaluationStudio.tsx`（前端交互：题数容量策略、动态全库覆盖选项、断点轮询恢复）
  - `run_lightrag_webui_server.py`（服务端网关：流式进度探测、任务取消与状态持久化）
- **状态：** 讨论与规划中

## 核心承诺
- **平台端改动：** 0 行代码修改（完全兼容 FastMCP 与上层消费端接口）
- **上游侵入度：** 0 行代码侵入（`lightrag/` 港大官方核心源码保持 100% 纯净）

## 方案概述

针对生产环境暴露出的三大矛盾（前端限制 25 题 vs 70 篇文档全覆盖需求、140 题串行耗时过长、无 Checkpoint 遭遇重启前功尽弃），本项目实施系统性优化：
1. **题量控制策略与交互重构**：提供“快速抽样模式（3~25题）”、“全库文档覆盖模式（1~2题/篇）”与“自定义数值输入（上限300题）”，彻底废除后端自作主张扩容 140 题的黑盒逻辑；
2. **异步并发流水线（Async Semaphore）**：引入并发控制（默认并发度 3~5），将大模型出题吞吐量提升 300%~500%；
3. **断点持久化与即时落盘（Checkpoint Recovery）**：每生成 1 题立即原子追加至临时断点文件，进程异常中止可无缝续传。
