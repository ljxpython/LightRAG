## 痛点剖析与架构决策

### 1. 现状痛点
- **痛点 1（指标混杂失真）：** 当前历史归档按创建时间做一维扁平列表展开，把简单基准考题与复杂业务多跳考题混在一起算“历史平均综合分”，失去数学统计与指导意义。
- **痛点 2（质量演进无追踪）：** 知识库在经过文档增删、切片策略调优或版本变更（`rev_1 -> rev_2`）后重新打擂，无法直观对比**同一评测集**在不同打擂轮次中的分数升跌（Quality Delta），无法进行质量回归验证。
- **痛点 3（模式优劣无天梯）：** 缺乏针对同一评测集横向对比 `mix`、`hybrid`、`naive`、`local` 各模式胜率与得分的收敛视图。
- **痛点 4（项目隔离与全局全景割裂）：** 只能看到当前项目下的记录，无法一键切换查看全部知识库项目或在不同项目间对比同名评测集的效果。

## 实施原则 (Karpathy & Production Guidelines)

1. **Simplicity First (KISS)：** 底层 SQLite 原生就有 `project_id`、`dataset_name` 等元数据，不需要新建任何数据库表或冗余字段，完全利用现成数据在前端做清晰的聚类与衍生指标计算。
2. **Surgical Changes：** 不破坏任何既有用例诊断抽屉、MLflow 深度比对链接和重跑打擂能力，只对列表展示和外层组织结构做外科手术式增强。
3. **DRY & SOLID：** 抽离统一的评测集指标聚类纯函数，确保最优分、涨跌幅、达标率计算逻辑一致且便于单测覆盖。
