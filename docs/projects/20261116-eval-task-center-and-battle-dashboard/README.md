## 方案概述

### 1. 痛点与背景
当前 WebUI 评测工坊（`EvaluationStudio`）的核心精力主要聚焦于“考题题库编排与切片透视”，而打擂评测（`matrix-run`）仅作为临时弹窗（Modal）存在。由此产生严重的体验断层：
1. **前台失忆**：用户一旦关闭打擂弹窗或刷新浏览器页面，正在进行的打擂任务在界面上“直接隐形”，无法获知当前进度（%）、耗时或流式日志；
2. **成果断层**：打擂完成后缺乏统一的成果列表与指标概览，用户必须肉身跳转外部 MLflow 或上宿主机翻 JSON/CSV 文件才能查看评分；
3. **缺少聚合概览**：缺乏以“单次打擂”为维度的全局综合得分、通过率（Pass Rate）及各个核心评估维度（Faithfulness、Answer Relevancy、Contextual Recall、Contextual Precision、Refusal / Counterfactual）的宏观卡片视图。

### 3. 数据契约与 API 接口规划

#### 3.1 数据库结构升级 (`catalog.sqlite` 中的 `eval_runs`)
扩展现有 `eval_runs` 表，增加聚合指标与诊断持久化字段：
- `overall_score REAL`：全量考题综合平均分 (0.0 ~ 1.0)
- `pass_rate REAL`：用例全项通过率 (0.0 ~ 1.0)
- `metrics_summary_json TEXT`：各个分项指标平均值 JSON（如 `{"faithfulness": 0.85, "answer_relevancy": 0.78, ...}`）
- `report_file TEXT`：落盘的 JSON 报告相对路径

#### 3.2 后端新增与改造接口
1. `GET /ops/evaluation/runs`
   - 查询当前项目（或全量项目）的打擂任务列表；
   - 融合返回：内存中运行中任务的最新 progress / live logs，以及 SQLite 历史任务持久化记录。
2. `GET /ops/evaluation/runs/{task_id}`
   - 获取单次打擂的完整用例评分大表、每道题的 Reason、Passed 状态及原汁原味的生成答案。
3. `POST /ops/evaluation/tasks/{task_id}/abort`
   - 发送信号优雅终止正在运行的子进程，释放系统与 LLM API 算力。
